# 新能源电车能耗账本 · v1 功能设计

> 版本：v1.0　日期：2026-11-20
> 上游依据：`微信小程序入门与AI搭建指南.md`
> 本文是 v1 页面行为与统计口径的权威说明。实现时若与指南冲突，以本文为准；产品决策变化时同步回写本文与指南。

---

## 1. 产品定义

**一句话**：给新能源车主一个「补能时记一笔，自动算百公里电耗和每公里成本」的轻量账本。

- **目标用户**：私家纯电/插混车主，家充与公共快充混用，想知道自己用车到底多费电、多费钱。
- **核心问题**：我这台车百公里几度电？每公里几毛钱？这个月和上个月比是涨了还是降了？
- **核心价值**：录入足够轻（≤30 秒一笔），统计口径固定可信，不需要连车、不需要 OBD。
- **非目标（v1 明确不做）**：多车切换、保养/保险/年检记账、行程轨迹、自动同步车企数据、社区分享、微信支付、登录注册页（用微信身份静默识别）。

## 2. 信息架构与导航

```
app.json tabBar（2 个 tab）
├── 记录  pages/list/index   ← 首页，默认进入
│     └── 右下角悬浮「+」 → pages/add/index（非 tab，navigateTo）
└── 统计  pages/stats/index
```

| 页面 | 路径 | 类型 | 职责 |
|---|---|---|---|
| 记录列表 | `pages/list/index` | tab 首页 | 按月份看明细与月汇总，进入记一笔 |
| 记一笔 | `pages/add/index` | 普通页 | 表单录入、校验、提交 |
| 统计 | `pages/stats/index` | tab | 近 6 个月趋势与花费结构 |

**为什么不做 3 个 tab**：表单页做成 tab 会让用户随时「误入」一个未完成的表单；「+」悬浮按钮是最短路径，也符合账本类产品习惯。

**二期补充页面**：`pages/import/index`（Excel 导入）与 `pages/export/index`（Excel 导出），入口在记录页顶部「导入数据 / 导出数据」。

**与指南的差异**：指南写「列表按月分组」。v1 改为**顶部月份选择器 + 当月明细**（组内再按日期分组）。原因：月度数据只需加载一个月，天然分页、月汇总口径不易出错；无限时间线分组需要跨页聚合，v1 不值得。若你更想要时间线，改动仅在列表页，统计与数据层不受影响。

## 3. 关键产品决策

| 决策 | 结论 | 理由 |
|---|---|---|
| 记录粒度 | **一次补能/一次里程 = 一条记录**；`chargeType=none` 表示只记里程、不充电 | 与指南数据模型一致；也支持「只想知道跑了多少」的用户 |
| 车辆 | v1 单车；`vehicles` 集合保留一条默认车，UI 不暴露切换 | 保留扩展性，避免 v2 迁移 |
| 派生指标 | **不落库**，`segmentKm` / 电耗 / 月汇总全部在云函数读取时实时计算 | 记录可删、可补录，落库会脏；实时算天然一致 |
| 排序 | 按 `date` 升序，同日按 `createdAt` 升序，再按 `_id` | 补录旧日期后，后续区间的里程自动重算 |
| 编辑 | v1 只支持删除，不支持编辑（v1.1 加） | 控制页面数量；删了重记即可 |
| 统计样本 | 只有「有本段里程」的记录参与效率计算；**全局第一条没有本段，不计入电耗/成本**，但仍计入总花费与总充电量 | 第一条之前没有里程，强行计入会虚高 |
| 登录 | 不设登录页，`wx.cloud.callFunction` 自动带 openid | 云开发能力 |
| 单位/币种 | km、kWh、元（¥）、日期 `YYYY-MM-DD` | 国内用户习惯；日期用字符串避开时区问题 |

## 4. 页面规格

### 4.1 记录列表 `pages/list/index`

```
┌─────────────────────────────────┐
│  ‹   2026年11月   ›     我的车   │  ← 月份切换 + 车辆名（只读）
├─────────────────────────────────┤
│  本月里程   本月电耗   本月花费    │
│  350 km    12.9        ¥90.00   │  ← 汇总卡（电耗无样本时显示「—」）
│            kWh/100km            │
├─────────────────────────────────┤
│  11月10日 周日                    │
│  ┌───────────────────────────┐  │
│  │ 快充  45.0 kWh   ¥60.00   │  │
│  │ 读数 10350 km · 本段 350 km│  │
│  │ 本段电耗 12.9 · 本段 ¥0.17/km│ │
│  └───────────────────────────┘  │
│  11月01日 周六                    │
│  ┌───────────────────────────┐  │
│  │ 家充  40.0 kWh   ¥30.00   │  │
│  │ 读数 10000 km · 首条记录    │  │
│  └───────────────────────────┘  │
│                                 │
│                        ( + )    │  ← t-fab，右下角，避让安全区
└─────────────────────────────────┘
```

**元素**

- 月份切换：点 ‹ / › 切月，不能切到未来；点中间月份可弹出年月选择器。切换时保留页面，重新拉取。
- 汇总卡三项：本月里程、本月电耗、本月花费（口径见 §5.3）。电耗无有效样本时显示「—」并附「再记一笔后可见」。
- 日期分组头：`M月D日 周X`，同日多条按创建时间倒序。
- 记录卡片：
  - 主行：充电类型标签（家充/快充/换电/未充电）+ 充电量 + 金额
  - 次行：里程读数（按 `odometerType` 显示「总里程」或「行程」）+ 本段里程
  - 第三行：本段电耗、本段每公里成本；首条记录显示「首条记录，无本段数据」
  - 金额为 0 时显示「¥0.00」而非隐藏（免费充电是有效信息）
- 左滑记录 → 删除（`t-swipe-cell`），二次确认，成功后局部移除并刷新汇总。
- 点击记录卡片：v1 不做详情页，无跳转。

**状态**

- 加载中：骨架屏（汇总卡 + 2 张卡片占位），不用全屏 loading。
- 本月无记录：`t-empty`「本月还没有记录」+「记第一笔」按钮。
- 拉取失败：`t-empty` 网络错误 +「重试」；保留上次成功数据并置灰，避免白屏。
- 下拉刷新：`enablePullDownRefresh`，仅刷新当前月。

### 4.2 记一笔 `pages/add/index`

```
┌─────────────────────────────────┐
│  ← 记一笔                        │
├─────────────────────────────────┤
│  日期        2026-11-20      >  │
│  里程类型    [总里程] [行程]      │  ← t-radio-group（分段）
│  里程读数    10350           km │
│  充电类型    [家充|快充|换电|未充电]│
│  充电量      45.0            kWh│
│  金额        60.00           元 │
│  电量区间    20% → 90%  （选填）  │
│  备注        ______________     │
├─────────────────────────────────┤
│  本段 350 km · 本段电耗 12.9     │  ← 实时预览（有上一条时）
│              [ 保 存 ]           │
└─────────────────────────────────┘
```

**字段与校验**

| 字段 | 控件 | 必填 | 规则 / 默认 |
|---|---|---|---|
| 日期 | 日期选择器 | 是 | 默认今天；不得晚于今天；不得早于 2000-01-01 |
| 里程类型 | 分段选择 | 是 | 默认「总里程」；记住上次选择 |
| 里程读数 | 数字键盘 | 是 | > 0，≤ 2,000,000，最多 1 位小数；标签随类型变为「总里程读数」/「本次行程里程」 |
| 充电类型 | 分段选择 | 是 | 家充 / 快充 / 换电 / 未充电；默认**上次使用的类型**（首次为家充） |
| 充电量 | 数字键盘 | 条件必填 | 充电类型≠未充电时必填，0 < x ≤ 200，最多 3 位小数；选「未充电」时置 0 并禁用 |
| 识别订单 | 文字按钮 | 否 | 选图 → DeepSeek 多模态 → 回填电量/金额/SOC/站点，里程有就填；识别失败可手动输入 |
| 金额 | 数字键盘 | 是 | 0 ≤ x ≤ 10,000，2 位小数；允许 0（免费/单位充电） |
| 电量区间 | 两个数字输入 | 否 | 0–100 整数；填了起止则要求结束 > 开始 |
| 备注 | 多行输入 | 否 | ≤ 100 字；显示字数 |

**交互规则**

- 表单为空时「保存」置灰；填写中不置灰，点击后逐项定位第一个错误并 toast 提示。
- 「里程读数」失焦时调用云端取上一条记录，实时显示「本段 xxx km · 本段电耗 xx.x」。取不到就显示「首条记录」。
- 保存中按钮 loading 且禁止重复点击；成功后 `toast('已记录')` + `navigateBack`，列表页 `onShow` 刷新。
- **编辑模式**：从列表点击记录进入 `/pages/add/index?id=...`，回填原值，标题改为「编辑记录」，保存调用 `updateRecord`；`createdAt` 保留，派生值在读取时重算，因此改日期或里程后后续区间自动更新。
- 失败保留全部输入，toast 错误原因，可重试。
- 键盘遮挡：输入框加 `cursor-spacing`，页面可滚动。
- 「未充电」时隐藏/置灰充电量，金额仍可填（例如停车费，可选填 0）。

## 5. 计算口径（实现时逐条对照）

### 5.1 排序与「上一条」

- 同一用户（openid）下，记录按 `date` 升序、`createdAt` 升序、`_id` 升序排列。
- 补录旧日期后，其后的记录本段里程会变化 —— 因为派生值不落库，这是预期行为。

### 5.2 本段里程 `segmentKm`

设当前记录为 `R[i]`：

| 情况 | 规则 |
|---|---|
| `odometerType = total` | 向前找最近一条 `odometerType = total` 的记录 `R[j]`；`segmentKm = R[i].odometer - R[j].odometer` |
| `odometerType = total` 且前面没有 total 记录 | `segmentKm = null`（视为首条总里程记录） |
| `odometerType = trip` | `segmentKm = R[i].odometer`（该字段存的就是本段行程），与上一条无关 |
| `segmentKm ≤ 0` 或 `> 2,000` | 标记为异常段：`segmentKm = null`，列表显示「里程异常」，不计入统计 |

> 混合类型允许存在：total 记录只和上一条 total 记录做差，不会被 trip 记录打断。

### 5.3 本段电耗与成本

```
本段电耗(kWh/100km) = R[i].chargeKwh ÷ segmentKm × 100     （segmentKm 有效且 chargeKwh > 0）
本段每公里成本(元/km) = R[i].chargeFee ÷ segmentKm          （segmentKm 有效）
```

- `chargeType = none` 或 `chargeKwh = 0`：本段电耗为 null，但本段里程有效，计入月里程。
- 金额为 0 是合法的，成本显示 ¥0.00。

**前提假设**（要写进产品提示，不要隐藏）：该口径默认每次记录时都充到相近电量（建议 SOC ≥ 90% 或固定值）。长期只充一半会让区间电耗明显偏低。电量区间字段是选填的辅助信息，v1 不做自动校正。

### 5.4 月度汇总

| 指标 | 口径 |
|---|---|
| 本月里程 | 本月所有**本段有效**记录的 `segmentKm` 之和（含未充电记录） |
| 本月电耗 | 本月**本段有效且 chargeKwh > 0** 的记录的 `ΣchargeKwh ÷ ΣsegmentKm × 100` |
| 本月花费 | 本月所有记录的 `chargeFee` 之和（**含首条**） |
| 本月充电量 | 本月所有记录的 `chargeKwh` 之和（**含首条**） |
| 每公里成本（统计页） | 所选区间内**本段有效**记录的 `ΣchargeFee ÷ ΣsegmentKm` |

> 为什么「本月电耗」的分子不是「本月充电量」：首条记录没有对应里程，若计入分子会虚高。页面上「本月充电量」展示的是全量，电耗用的是有效样本，两者可能不同，这是刻意设计，不要“修正”。

### 5.5 计算示例

| 记录 | 日期 | 类型 | 读数 | 充电量 | 金额 | 本段里程 | 本段电耗 | 本段成本 |
|---|---|---|---|---|---|---|---|---|
| A | 11-01 | total | 10000 | 40.0 | 30.00 | null（首条） | — | — |
| B | 11-10 | total | 10350 | 45.0 | 60.00 | 350 | 12.9 | ¥0.17 |

11 月汇总：里程 350 km；电耗 45 ÷ 350 × 100 = **12.9**；总充电量 85.0 kWh；总花费 **¥90.00**；每公里成本 60 ÷ 350 = **¥0.17**。

注意总花费含 A 的 30 元，成本却只算 B 的 60 元 —— 这正是首条记录只计入流水、不计入效率的口径。

### 5.6 数值与展示

- 电耗保留 1 位小数，成本 2 位，金额 2 位，kWh 1 位，里程取整显示。
- 计算全程用浮点，展示时再四舍五入；不要用展示值再参与下一步计算。
- 分母为 0 或 null 一律显示「—」，不显示 0 或 Infinity。
- 月份归属：本段数据归**后一条记录**所在的月份；跨月的段整段计入后一条记录所在月。

## 6. 数据模型与云函数

### 6.1 集合

```js
// vehicles —— v1 每个用户一条默认车
{
  _id, _openid,
  name: '我的车', model: '', batteryKwh: null, plateNo: '',
  createdAt
}

// records —— 冗余 _openid 便于权限与查询
{
  _id, _openid, vehicleId,
  date: 'YYYY-MM-DD',
  odometer: Number,
  odometerType: 'total' | 'trip',
  chargeKwh: Number,          // 最多 3 位小数
  chargeFee: Number,
  chargeType: 'home' | 'fast' | 'swap' | 'none',
  socStart: Number | null,
  socEnd: Number | null,
  note: String,
  createdAt: Date,            // 手工=服务端时间；导入=原始充电时间
  updatedAt: Date,
  source: 'manual' | 'import',
  importFingerprint: String,  // 仅导入记录，用于去重
  importBatch: String         // 仅导入记录，用于按批次清理/撤销
}
```

- 索引：`records` 建复合索引 `_openid + date`；`vehicles` 建 `_openid`。
- 数据库权限：控制台设为「仅创建者可读写」。云函数使用管理员权限，**必须在每个查询里手动带上 `_openid = wxContext.OPENID`**，不能依赖数据库权限。
- 不采集位置、车牌可空、备注原样存储；不向第三方发送任何用户数据。

### 6.2 云函数

**实现采用单个 `ledger` 云函数 + `action` 分发**，而不是 5 个独立函数。原因：`segmentKm`、月汇总、统计必须共用同一份计算逻辑；拆成 5 个函数会把 calc 复制五份，口径极易漂移。前端统一通过 `miniprogram/utils/ledger.js` 调用。

目录：`cloudfunctions/ledger/index.js`。

**统一响应**：`{ code: 0, data }`；业务错误 `{ code: 4xx, message }`，前端直接 toast `message`，不暴露堆栈。

| action | 入参 `payload` | 返回 `data` | 说明 |
|---|---|---|---|
| `setup` | 无 | `{ vehicle }` | 创建集合与默认车；部署后调用一次 |
| `ensureVehicle` | 无 | `{ vehicle }` | 幂等，首次创建默认车 |
| `addRecord` | 见下 | `{ _id, segmentKm, prevOdometer, consumption, costPerKm }` | 服务端二次校验；返回本段结果 |
| `getRecord` | `{ _id }` | `{ record }` | 编辑页回填；校验归属 |
| `updateRecord` | `{ _id, ...字段 }` | `{ _id }` | 服务端二次校验；保留 `createdAt` / `importFingerprint` |
| `listRecords` | `{ month: 'YYYY-MM' }` | `{ month, vehicle, summary, records }` | 该月记录 + 月汇总，记录已带本段派生值 |
| `getStats` | `{ months: 6 \| 0 }`（0=全部） | `{ currentMonth, months, totals, byType }` | 趋势与花费构成 |
| `deleteRecord` | `{ _id }` | `{ deleted: true }` | 校验 `_openid` 归属，非本人返回 403 |
| `importRecords` | `{ fileID \| fileBase64, defaultChargeType, importBatch? }` | `{ totalRows, imported, skippedDuplicate, skippedInvalid, errors, insertedIds, importBatch }` | 解析 Excel、去重、批量写入 |
| `deleteImportBatch` | `{ importBatch }` | `{ deleted, importBatch }` | 按批次删除（测试清理 / 未来撤销导入） |
| `exportRecords` | `{ month?, returnBase64? }` | `{ fileID \| base64, count, fileName }` | 生成与导入模板兼容的 Excel |
| `recognizeChargeOrder` | `{ fileID \| imageBase64 }` | `{ fields, recognized, model }` | DeepSeek 多模态识别充电订单，返回归一化字段 |

调用方式：`wx.cloud.callFunction({ name: 'ledger', data: { action, payload } })`。

`addRecord` 请求示例：

```js
{
  date: '2026-11-20',
  odometer: 10350,
  odometerType: 'total',
  chargeKwh: 45,
  chargeFee: 60,
  chargeType: 'fast',
  socStart: 20,
  socEnd: 90,
  note: ''
}
```

`listRecords` 返回的 summary 字段：

```js
{
  month: '2026-11',
  distanceKm: 350,
  chargeKwh: 85.0,       // 全量
  fee: 90.0,             // 全量
  consumption: 12.9,     // 有效样本，可为 null
  costPerKm: 0.17,       // 有效样本，可为 null
  recordCount: 2
}
```

`getStats` 返回：

```js
{
  currentMonth: '2026-11',
  months: [{ month, distanceKm, chargeKwh, fee, consumption, costPerKm }],
  totals: { distanceKm, chargeKwh, fee, consumption, costPerKm, recordCount },
  byType: { home: { kwh, fee }, fast: { kwh, fee }, swap: { kwh, fee }, none: { kwh, fee } }
}
```

**实现要点**

- 计算口径集中在 `ledger/index.js` 的 `computeRecords` / `summarize`，所有 action 共用，天然避免三处漂移。
- 本段里程依赖前一条记录，因此读取时拉取该用户全量记录再在内存里算（个人账本量级足够）；单用户超过约 2000 条再改为按月增量与聚合缓存。
- `setup` 通过 `db.createCollection` 创建 `records` / `vehicles`，冷启动只执行一次；索引仍需在云开发控制台手动创建。
- `createdAt` 用 `db.serverDate()`，不信任客户端时间；「今天」按东八区计算。

## 7. 校验与异常矩阵

| 场景 | 前端 | 云端 | 展示 |
|---|---|---|---|
| 必填未填 | 阻止提交，定位字段 | 二次校验兜底 | toast + 字段红字 |
| 里程 ≤ 0 / 非数字 | 阻止 | 拒绝 | 「里程需大于 0」 |
| 里程读数小于上一条 total 记录 | **允许**，弹确认「读数小于上一条，确认继续？」 | 允许 | 该段标记异常，不计入统计 |
| 日期晚于今天 | 选择器禁用 | 拒绝 | — |
| 充电量 0 但类型不是未充电 | 提示改为「未充电」或填电量 | 拒绝 | toast |
| 金额 0 | 允许 | 允许 | 显示 ¥0.00 |
| 重复记录（同日期 + 同读数 + 同电量） | 弹确认 | 允许（用户可能真的同一天两次） | — |
| 网络/云函数失败 | 保留输入 | — | toast + 可重试 |
| 云环境未初始化 | 启动时检测 | — | 全屏错误页「云开发环境未配置」 |
| 删除他人记录 | — | 校验 openid，拒绝 | 「无权限」 |
| 统计样本不足 | — | 返回 null | 显示「—」与引导文案 |

**云端校验必须独立实现**，不能只依赖前端；金额与电量做上限保护，防止误输（如 4500 kWh）。

## 13. 二期功能实现说明

### 13.1 历史记录编辑

- 列表记录卡片可点击 → `/pages/add/index?id=<id>`，表单回填原值，标题改为「编辑记录」。
- 云函数 `getRecord` / `updateRecord` 校验归属；更新时保留 `createdAt`、`importFingerprint`、`vehicleId`，只改业务字段。
- 派生指标（本段里程、电耗、月汇总）不落库，编辑后读取时自动重算，后续记录同步受影响。
- 编辑已导入的 3 位小数充电量不会丢精度。

### 13.2 Excel 导入

- 入口：记录页「导入历史数据」；页面 `pages/import/index`。
- 选择文件：`wx.chooseMessageFile`，仅 `.xlsx/.xls`，≤5MB；先发送到微信「文件传输助手」。
- 上传云存储后调用 `ledger.importRecords`，导入完成删除临时文件。
- 读取工作表：优先「充电数据」，否则第一张；自动搜索表头行（最多前 20 行），按列名映射而不是固定列序。

| 模板列 | 映射 | 规则 |
|---|---|---|
| 充电时间 | `date` / `createdAt` | 支持 `YYYY-MM-DD HH:mm` 字符串、Excel 日期序列；完整时间用于同日排序 |
| 总里程(公里) | `odometer` | 必填，>0，最多 1 位小数 |
| 里程类型 | `odometerType` | 可选；「行程」→ trip，否则 total |
| 充电类型 | `chargeType` | 可选；家充/快充/换电/未充电，否则按备注推断 |
| 充电前电量(%) | `socStart` | 可选；非法时整对置空 |
| 充电后电量(%) | `socEnd` | 可选；要求 0–100 且大于起点 |
| 充电度数(度) | `chargeKwh` | 必填，>0，≤200，保留 3 位小数 |
| 充电金额(元) | `chargeFee` | 必填，0–10000，保留 2 位 |
| 备注 | `note` | 截断 100 字；用于推断充电类型 |
| 车端电量 / 电费单价 | 忽略 | — |

- 充电类型推断：`换电` → swap；`家充/家冲` → home；`超充/快充/充电站/充电桩` → fast；否则用页面选择的默认类型。
- 去重：`importFingerprint = sha1(完整时间|里程|电量|金额)`；已存在的指纹跳过。
- 返回结果包含 `insertedIds` 与 `importBatch`；测试清理或未来「撤销导入」可按批次删除。UI 展示读取/成功/重复/无效行数和前 20 条错误。
- 模板中的「收支明细」工作表本期不导入，属于后续费用模块。

### 13.3 充电订单截图识别（DeepSeek 多模态）

- 入口：记一笔/编辑页顶部「识别充电订单截图」；`wx.chooseMedia` 拍照或相册，压缩后上传云存储。
- 云函数 `ledger.recognizeChargeOrder`：
  - 读取 `DEEPSEEK_API_KEY`；`DEEPSEEK_MODEL` 默认 `deepseek-flash`，`DEEPSEEK_BASE_URL` 默认 `https://api.deepseek.com`。
  - 图片以 base64 data URL 放入 `user` 消息的 `image_url`，请求 `POST /chat/completions`。
  - 提示词要求只输出 JSON，字段为 `date/time/odometer/chargeKwh/chargeFee/socStart/socEnd/chargeType/station/note`；明确不提取订单号、手机号、账号、支付方式、车牌。
  - `lib/order.js` 解析 JSON（兼容 Markdown 代码块）并做范围归一化，不确定的字段直接丢弃。
- 客户端回填表单：日期、总里程（有才填）、充电量、金额、SOC、充电类型、备注（站点 + 备注）。
- **识别结果预览**：保留本地截图缩略图，可点开 `wx.previewImage` 查看原图；同时列出识别到的字段，供人工核对。识别内容不会自动保存。
- 截图没有里程时，里程字段留空，由用户手动填写。
- 未配置 Key、401、402/429 或调用超时都返回业务错误，页面 toast 并保留手动输入路径。
- 云端临时文件无论成功失败都会删除；截图会发送给 DeepSeek，隐私指引需声明第三方 AI 处理与临时存储。

### 13.4 Excel 导出

- 入口：记录页「导出数据」→ `pages/export/index`；范围可选「全部记录」或「指定月份」。
- 云函数 `exportRecords` 使用同一套 `xlsx` 生成单 sheet「充电数据」，列与导入模板兼容，并额外导出「里程类型」「充电类型」，保证导出文件可再次导入。
- 导出列：充电时间、总里程(公里)、里程类型、充电类型、充电前/后电量、充电度数(度)、车端电量(度)、充电金额(元)、电费单价(元/度)、备注。
- 时间：导入记录保留原始时分；手工记录只输出日期。电量保留 3 位、金额 2 位、单价 4 位。
- 生产路径：上传云存储 → 客户端 `wx.cloud.downloadFile` → 删除云端临时文件 → `wx.openDocument({ showMenu: true })` 打开/保存，或 `wx.shareFileMessage` 发送到聊天。
- 返回 `{ fileID, count, fileName }`；`returnBase64` 仅用于测试，可直接解析工作簿校验内容。
- 空范围返回业务错误「所选范围没有可导出的记录」，不生成空文件。
